
## 3. Решение проблемы разнородного оборудования — HAL

Для обеспечения совместимости облачного POS с разнородным оборудованием магазинов предлагается внедрить **Hardware Abstraction Layer (HAL)** — локальный программный слой, который выступает посредником между кассовым приложением и физическими устройствами.

HAL предоставляет единый API для взаимодействия с фискальными регистраторами, банковскими терминалами, сканерами штрихкодов и принтерами чеков независимо от производителя и модели оборудования.

### Архитектура решения

**1. Web POS / Tablet App (тонкий клиент)**

- Отображает интерфейс кассира и управляет процессом продажи.
- Отправляет команды в HAL через унифицированный локальный API.
- Не содержит специфических драйверов оборудования.
- Не зависит от конкретного производителя терминала или фискального регистратора.

**2. Hardware Abstraction Layer (HAL)**

- Принимает команды от POS через REST API или локальный IPC.
- Определяет тип и модель подключённого оборудования.
- Выбирает соответствующий адаптер устройства.
- Преобразует универсальные команды POS в команды конкретного драйвера или SDK.
- Нормализует ответы и ошибки оборудования в единый формат.
- Контролирует состояние устройств и предотвращает повторное выполнение критичных операций.

**3. Hardware Adapters (адаптеры оборудования)**

Для каждого типа оборудования реализуется отдельный адаптер:

| Тип оборудования | Примеры | Назначение адаптера |
|---|---|---|
| Фискальные регистраторы | АТОЛ, Штрих-М | Фискализация продаж, возвратов и печать чеков |
| Банковские терминалы | Ingenico, Verifone | Выполнение карточных платежей через соответствующие SDK |
| Банки-эквайеры | Сбербанк, Альфа-Банк | Интеграция с банковскими протоколами и платёжными приложениями |
| Сканеры штрихкодов | USB, Bluetooth | Считывание и передача штрихкодов в POS |
| Принтеры ценников | USB, Ethernet | Печать ценников по унифицированным шаблонам |

### Унифицированный API HAL

POS обращается к оборудованию через единые интерфейсы независимо от конкретной модели устройства.

| Метод | Назначение |
|---|---|
| `scanBarcode()` | Получение штрихкода товара |
| `printFiscalReceipt()` | Фискализация продажи и печать чека |
| `startCardPayment()` | Запуск оплаты банковской картой |
| `refundPayment()` | Выполнение возврата платежа |
| `getDeviceStatus()` | Получение статуса подключённого устройства |
| `printPriceLabel()` | Печать ценника |

### Пример взаимодействия

1. Кассир выбирает оплату банковской картой в Web POS.
2. POS вызывает унифицированный метод `startCardPayment()`.
3. HAL определяет подключённый банковский терминал и необходимый протокол эквайера.
4. Соответствующий адаптер выполняет команду через SDK производителя или банковский протокол.
5. Терминал обрабатывает платёж и возвращает результат.
6. HAL преобразует результат в единый формат и передаёт его POS.
7. POS завершает продажу и инициирует фискализацию через `printFiscalReceipt()`.

При замене терминала Ingenico на Verifone потребуется настроить или заменить адаптер HAL, но бизнес-логика Web POS останется неизменной.

### Размещение HAL

HAL размещается локально в магазине одним из способов:

- **Native Agent на кассовом устройстве** — если операционная система поддерживает необходимые драйверы и SDK.
- **Edge Gateway** — компактное локальное устройство, обеспечивающее взаимодействие с USB/COM-оборудованием при использовании Web POS или планшетов.

Edge Gateway не содержит полноценной серверной базы данных магазина и не выполняет функции центрального POS Backend.

### Интеграция с облаком

В Cloud Backend размещается **Payment Orchestrator / Payment Gateway**, отвечающий за централизованную интеграцию с платёжными провайдерами, управление платёжными операциями и их статусами.

При этом необходимо разделять ответственность:

- **Локальный HAL** — физическое взаимодействие с оборудованием и SDK.
- **Cloud Payment Gateway** — централизованная логика обработки и маршрутизации платежей.
- **POS Backend** — управление бизнес-операциями продажи и их состояниями.

В онлайн-режиме компоненты взаимодействуют с облачной системой, а при потере интернета HAL продолжает обеспечивать локальную работу фискального регистратора для наличных продаж.

### Безопасность и надёжность

- Доступ к HAL разрешён только доверенным кассовым приложениям с аутентификацией и авторизацией.
- Для сетевых соединений используется защищённый транспорт.
- Критические операции имеют уникальные идентификаторы для предотвращения повторной оплаты или фискализации.
- HAL сохраняет технический статус выполнения операций и обеспечивает возможность его проверки после сбоя.
- Данные банковских карт не сохраняются в POS или HAL; обработка выполняется сертифицированными платёжными компонентами.
- Адаптеры оборудования тестируются и сертифицируются с поддерживаемыми моделями устройств.

### Результат

Внедрение HAL позволяет:

1. **Унифицировать работу с оборудованием** разных производителей и банков-эквайеров.
2. **Исключить зависимость POS от конкретных драйверов** и моделей устройств.
3. **Сократить время подключения новых магазинов** за счёт повторного использования готовых адаптеров.
4. **Упростить замену оборудования** без изменения бизнес-логики кассового приложения.
5. **Обеспечить offline-фискализацию** наличных продаж через локальное оборудование.
6. **Снизить TCO** за счёт централизованного сопровождения POS и отказа от устаревших локальных серверов.

**Итог:** HAL изолирует специфику оборудования от кассового приложения, обеспечивая единую модель интеграции для всех магазинов VitaStore независимо от используемых фискальных регистраторов и банковских терминалов.
