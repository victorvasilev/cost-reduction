
## 4. Offline-mode strategy

При отключении интернета POS автоматически переключается в автономный режим (Offline Mode), используя локальный Offline Transaction Engine, защищённый кэш товаров и цен, а также Hardware Abstraction Layer (HAL) для взаимодействия с оборудованием.

### Доступность операций в Offline Mode

| Операция | Доступность без интернета | Механизм реализации |
|---|---|---|
| Поиск товара по штрихкоду | Да | Поиск в локальном кэше каталога товаров |
| Расчёт цены | Да | Использование последнего действительного снимка цен |
| Оплата наличными | Да | Локальная обработка продажи через Offline Transaction Engine |
| Формирование фискального чека | Да | Взаимодействие с локальным фискальным регистратором через HAL |
| Банковская оплата | По умолчанию нет | Возможна только при поддержке сертифицированного автономного режима терминала и эквайера |
| Применение скидок и промоакций | Частично | Только заранее загруженные и разрешённые для автономной работы правила |
| Начисление и списание бонусов | Ограничено | Операции, требующие проверки актуального баланса в облаке, блокируются |
| Создание новых заказов Click & Collect | Нет | Требуется подтверждение резервирования в Smart Fulfillment |
| Передача продаж в ERP | Отложена | Операции сохраняются в локальном Outbox до восстановления соединения |
| Обновление каталога и цен | Нет | Используется последняя валидная локальная версия |

### Обработка продажи в автономном режиме

1. POS обнаруживает потерю соединения с Cloud Backend и переходит в Offline Mode.
2. Кассир сканирует товар, POS получает информацию из локального каталога.
3. Offline Transaction Engine рассчитывает стоимость на основании действующего снимка цен.
4. Покупатель оплачивает покупку наличными.
5. POS через HAL передаёт команду фискальному регистратору.
6. Фискальный регистратор формирует фискальный чек с использованием фискального накопителя.
7. После подтверждения фискализации сведения о продаже сохраняются в локальном Outbox со статусом `SYNC_PENDING`.
8. После восстановления соединения операции отправляются в Cloud Backend для синхронизации с ERP.

### Обеспечение надёжности

- **Local Cache:** локальное хранение каталога, штрихкодов, цен и разрешённых промоакций с контролем версий и срока действия.
- **Durable Outbox:** защищённое постоянное хранение операций до подтверждения их получения облаком.
- **Idempotency:** уникальный `transactionId` каждой продажи предотвращает повторное проведение операции в Cloud Backend.
- **Retry Mechanism:** автоматическая повторная отправка неподтверждённых операций при восстановлении связи.
- **Fiscal Safety:** перед повторной фискализацией проверяется состояние предыдущей операции, чтобы избежать повторного формирования чека.
- **Data Reconciliation:** после синхронизации проверяются количество чеков, суммы продаж, идентификаторы операций и расхождения с ERP.
- **Graceful Degradation:** при отсутствии интернета доступны только операции, которые могут быть безопасно выполнены локально.
- **Offline Restrictions:** при отсутствии действительного кэша цен, недоступности ККТ или невозможности надёжно сохранить операцию продажа блокируется.

### Результат

Магазин продолжает обслуживать покупателей за наличные даже при отсутствии интернета, сохраняя возможность выдачи фискальных чеков.

После восстановления соединения накопленные операции автоматически и идемпотентно передаются в Cloud Backend, что позволяет избежать повторного проведения продаж и обеспечить согласованность данных с ERP.

При этом в магазине не требуется полноценная серверная БД: достаточно защищённого локального хранилища на кассовом устройстве и HAL для работы с оборудованием.
